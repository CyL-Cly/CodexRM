# 2026-11-18 手机蜂窝网络 ↔ 本机 P2P 验证

本文使用真实手机与当前电脑验证数据路径。参考 `docs/p2p-nat-traversal-plan.md` 和 `docs/plans/2026-11-18-agent-android-p2p.md`；既有报告中的理论成功概率不作为实测结果。

## 范围

- 手机：通过 USB 连接的 OPPO PFFM20，arm64-v8a，Android API 36。
- 默认网络：电信 `ctnet` 5G 蜂窝网络；开始时 Wi-Fi 接口关闭、无 VPN。
- 电脑：Windows，走物理以太网及现有路由器；相关公网目标路由未走电脑已有的 WireGuard 接口。
- Android 独立测试包 `com.codexrm.p2pprobe`，Java Activity + 共享 Go 核心的 NDK/JNI 动态库。生产 `com.codexrm.mobile`、配对数据和 Agent/RM 业务代码没有因本实验被替换。
- 信令临时经 `adb reverse` 访问电脑 loopback HTTP，只交换候选、临时认证材料、就绪状态及测试统计。**UDP 探测、QUIC 和业务测试负载全部走双方公网 IPv4，不经 USB/TURN/RM 数据中继。**
- 这是网络与共享核心 PoC；尚未接入正式 RM 信令和 Agent 的 Codex RPC 分发器。测试 RPC 为 echo/reverseEcho，不代表正式客户端功能已完成。

## NAT 行为证据

手机使用同一个 UDP socket 访问 `162.159.207.0:3478`、`162.159.207.1:3478`，记录目标切换前后的映射及再次访问第一个目标的映射。观察到不同目标对应不同公网端口，重复同一目标的端口保持不变。这支持 **目标相关映射 EDM，即本实验所指的 Symmetric 类映射**，但没有完整区分 ADM/APDM，也没有完成手机全部过滤行为诊断。

电脑同一个 socket 访问可控 STUN 的两个端口及两个 Cloudflare 公网 IP，公网映射保持一致。另做 CHANGE-PORT 对照：

1. 尚未向替代端口发送时，其回包超时。
2. 向替代端口主动发送后，正常回包成功。
3. 再向原端口发送 CHANGE-PORT 请求，替代端口的响应成功到达，公网映射不变。

这组观察支持电脑路径的 **EIM + 端口相关过滤，即 Port Restricted Cone 行为**。诊断是对当前有效网络路径的观察，不保证网络配置永不变化。

## 固定实验方法

探索阶段先完成 5 回合多 socket 和 3 回合单 socket 的真实直连，再用两个可达的不同 STUN IP 做 3 回合参数确认。探索不纳入下面的固定验证统计。

固定验证计划 200 回合，参数为：

| 参数 | 值 |
| --- | --- |
| 每回合总截止时间 | 20 秒，包括建 socket、诊断、协调、打洞、QUIC 与 RPC |
| 电脑 socket | 1 个，STUN/探测/QUIC 不换 socket |
| 手机 socket | 最多创建 256 个；命中后保留选中者并关闭其他 socket |
| 电脑不同目标端口预算 | 2048，候选优先、邻域预测优先、随后随机无放回 |
| 邻域预测半径 | 每个已观测手机候选端口 ±64 |
| 发包节奏 | 调度 tick 5ms；手机逐 socket 轮询，整轮后间隔 1 秒 |
| 身份验证 | 探测 HMAC；QUIC TLS 1.3，双端证书及精确 SHA-256 pin |
| 业务成功条件 | 随机 32 KiB 上传 SHA-256 匹配，正向 RPC、反向 RPC、双方完成确认 |
| 新回合 | 新 session round、新电脑 socket、新手机 socket 集合 |

两端分别记录每一回合；只有同一回合双方均报告完整成功才计入分子，不把两个端点算作两个样本。每个新回合不重置运营商的端口块、基站或公网 IP。

`hitPhase` 用来区分候选、邻域预测、随机阶段。早期命中时很多手机 socket 尚未发包；“创建 256 个 socket”不能解释为“证明同时存在 256 个公网映射”。

## 固定验证结果

**194 / 200 回合完成真实直连，成功率 97%，达到这组设备的 >50% 要求。** 名义 95% Wilson 区间为 **93.61%–98.62%**。200 回合全部完成、无缺失；6 个失败回合全部计入分母。手机私有目录中的 200 条本地结果已与电脑记录逐条核对一致。

| 指标 | 实测 |
| --- | --- |
| 总回合 / 成功 / 失败 | 200 / 194 / 6 |
| 总耗时 P50 / P90 / P95 | 2.682 / 4.957 / 5.463 秒，含诊断和失败回合 |
| 成功打洞阶段 P50 / P90 / 最长 | 0.159 / 0.355 / 1.418 秒，不含 QUIC/RPC |
| 候选阶段命中 | 9 回合 |
| 邻域预测阶段命中 | 185 回合 |
| 随机阶段命中 | 0 回合；不构成随机生日模式的成功率证明 |
| 手机同 socket 的跨目标映射不同 | 169 回合有直接证据；其他回合有超时或同端口观察，不能强行归类 |
| 电脑映射跨已观察目标稳定 | 200 回合 |
| 电脑替代来源端口被过滤 | 198 回合；其余 2 回合收到替代端口回复，不能声称每回合均具全新过滤状态 |

分段结果：1–50 为 50/50，51–100 为 50/50，101–150 为 49/50，151–200 为 45/50。后半段出现更多 STUN 不可用，不能只展示前段连续成功的结果。

失败详情：

- 第 132 回合：UDP 打洞超时，手机成功探测发包计数为零。初版没有保存具体发送错误，不能据此确定是运营商过滤、路由变化或本地发送异常。
- 第 153、183、185、187、190 回合：手机所有本轮 STUN 请求均超时，没有取得候选。未排除网络抖动、服务端限速等原因，未把它们剔出直连分母。
- 截止时间为 20 秒；超时回合的退出清理最多额外记录约 100ms，因此最长失败总耗时为 20.100 秒。没有在截止后继续打洞并计成功。

初步观察：手机已观测映射端口的跨度仅 125，且多数成功发生在候选附近。这支持优先使用小窗口探测，但不能据此证明运营商永久使用固定大小端口块，也不能把 97% 外推到全范围随机分配或其他运营商。

统计由 `tools/p2p-probe/scripts/analyze.py` 生成，汇总为 `.work/p2p-20261118/validation-200/summary.json`，配对原始记录为同目录 `rounds.jsonl`。实验批次中未更换参数或因失败重启计数。

## 与参考报告相比的具体修正

- 两个相同公网 IP 的 STUN 端口不足以证明 EIM；本实验增加不同公网 IP 的同 socket 对照。
- 不把“256 个 socket”自动视为 256 个有效映射，也不把理想生日碰撞概率作为设备成功率。
- 不默认固定本地端口/SO_REUSEADDR 可以跨重启复用 NAT 映射；验证回合主动重建端点。
- 不假设 QUIC 自动提供跨 Wi-Fi/蜂窝无缝迁移；本次仅验证同一网络路径上的建连与业务。
- 正式 Android 当前并无报告所述的常驻前台服务；本实验使用前台测试 Activity。
- 正式业务路径切换还需撤销同步、请求去重和在途 RPC 处理；streamId 本身不提供幂等性。

## 产物与边界

- 可复用源码：`tools/p2p-probe/`，独立 `go.mod`，quic-go 固定 `v0.59.1`，不改变根模块依赖。
- 私有原始数据、临时配置/密钥、APK 和 Windows 二进制：`.work/p2p-20261118/`。
- 可控临时 STUN 服务已关闭，本次添加的防火墙规则已撤销；USB reverse 和手机临时配置已移除。独立测试应用已停止并切回原 CodexRM 应用，保留测试 APK 和本地结果以便审阅。
- 单台手机、单运营商、单地点的连续实验；不代表所有运营商或随机端口分配环境。相邻回合可能相关，置信区间只作名义统计参考。
- 尚未测试真实 Codex 命令/审批/附件、30 分钟空闲保活、多客户端、Wi-Fi/蜂窝切换、RM 不可达或撤销租约。
